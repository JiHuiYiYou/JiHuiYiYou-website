01 / Why JHYY

A language, not a framework.

Four opinions we won't compromise on. Each is a small, specific promise — not a marketing tagline.

01 Type system

Static, not gradual.

Types are checked at compile time. There is no any, no implicit conversion, no escape hatch. If a value is i32, it is i32 for the rest of the program.

anydoes not exist
implicit conversionnone
escape hatchnone
02 Control flow

Expressions, not statements.

if, match, and blocks return values. The last expression of a function is its return — no return keyword needed.

if / match / blocks → all values
03 Trajectory

A compiler that compiles itself.

The compiler is written in itself. It compiles itself, then compiles itself again, and the gate requires the emitted assembly to be byte-identical across generations. The fixed point is reached, not assumed — the local gate iterates N=10 generations.

C host → JHYY host → Byte-equal closure ✓

03 / A taste of the language

Four files, the whole grammar.

hello.jhyy 
extern fn puts(s: *u8) -> i32;

fn main_jhyy() -> i32 {
    puts("Hello, world!");
    0
}
type Point = struct { x: i32, y: i32 }

fn dist_sq(a: Point, b: Point) -> i32 {
    let dx = a.x - b.x;
    let dy = a.y - b.y;
    dx * dx + dy * dy
}

fn main_jhyy() -> i32 {
    dist_sq(Point { x: 3, y: 4 }, Point { x: 0, y: 0 })
}
fn fib(n: i32) -> i32 {
    if n < 2 { n }
    else { fib(n - 1) + fib(n - 2) }
}

fn main_jhyy() -> i32 { fib(10) }
type Option = enum {
    Some(i32),
    None,
}

fn unwrap(o: Option) -> i32 {
    match o {
        Some(v) => v,
        None    => 0,
    }
}

fn main_jhyy() -> i32 {
    unwrap(Option::Some(99))
}

04 / The toolchain

A compiler, and everything around it.

You don't only get jhyy.exe. You get an editor extension, an MCP server for Claude Code, and an arena runtime — the four pieces a real language needs to be usable.

Compiler

jhyy compile foo.jhyy -o foo.exe runs the pipeline: Lex → Parse → Sema → IL → self-written amd64 emitter → native. Diagnostics carry line + column. Exit codes match clang. No GC, no malloc hot-path — one arena_alloc, one arena_free at the end.

The arena runtime

The allocator is a lifetime tool too: arena_alloc once, arena_free at the end, while arena_reset (reuse the memory) and arena_free (release the whole block) each own their own ground — the arena deep dive lays the boundaries out. 05 / Status and boundaries

What works, and what doesn't.

JHYY is a pre-1.0 project: self-hosting holds and the regression suite is green, but it is not yet a replacement for C or Rust. This screen states both sides — talking only about what works is the same as not talking.

✗ Not there yet

The boundaries, stated plainly

amd64 only — no aarch64, no riscv, no wasm. The host is Windows x64. The UEFI entry path is not finished (ABI § 12.8). No traits, no GC, and the borrow check is currently only a minimal first layer. The installer and the MSI are unsigned. Bare-metal support stops at the freestanding mode; linking still needs an external ld.

Bare-metal capabilities today
→ In flight

Three directions, at once

The ARM target lives in the for-VEX project — JHYY emits ARM machine code directly and links the official SDK. The operating system's design baseline is being rebuilt; all it has today is one UEFI x64 boot spike. The IDE puts blocks and text on the same AST.

See the family's other three projects
◆ An important distinction

What “byte-identical” actually proves

The self-hosting closure proves generational determinism — the compiler reproduces itself exactly. That is a statement about determinism, not about semantic correctness; semantic correctness is covered separately by the regression suite. This is the classic trusting trust gap, and the two must not be conflated.

06 / By the numbers

No VM. No JIT. No runtime.

The self-written emitter produces amd64 machine code directly at compile time. The bundled runtime is only a small C support library (about 156 lines), and even that can be left out — under #[no_std] no C runtime is linked. 1.42× – 5.37×
9 tasks over 4 coverage axes (integers and bit operations, f64, heap, bytes), min-of-15 wall clock. This is a code-quality lower bound, not a speed pass line — see the note below.

About this ratio: JHYY has no optimizer yet and produces code close to -O0, so gcc -O0 is the only denominator on the same scale; gcc -O2 is a reference point, not a pass/fail standard. The ratio subtracts the measurement floor (process creation + runtime startup; JHYY's shim costs about 6 ms more than plain C). For ack and nq the floor is over 25% of the measurement, so the ratio is unreliable and is not reported. These tasks measure code generation, not standard library quality — the standard library is a separate axis. The full snapshot is in the repository at bench/baseline/RESULTS-2026-11-04.md.

09 / About

Beijing · RDFZ ICC · CS,
one compiler, and the OS behind it.

The author of 机会翼游 (JHYY). Two years ago I saw a talk about the z language on Bilibili, took some inspiration from it, and started JHYY. At first there was no clear direction; it took shape gradually: rust-like plus an arena allocator, and later a self-hosting-first policy — and now it does self-host: the compiler's only implementation is JHYY itself, the two generations are required to be byte-identical, and the fixed point is run to. The backend is also my own amd64 emitter, about 13,400 lines, with no LLVM and no vendored QBE.

What to do after self-hosting? Leveraging strong typing and fast compiles, we started sketching an OS of our own. Three directions were settled on — Cap<T> capabilities, a lang-debug ABI, and a GUI — aiming at the JiHuiYiYou-OS microkernel.

Outside the compiler I occasionally make Godot indie games too. You can find me on GitHub.

The project is young — right now it is still a one-person outfit. Suggestions, discussion and contributions are all welcome.
