A systems language that compiles itself — four projects share it.

JHYY (机会翼游) is a statically typed, expression-oriented systems programming language. The compiler is written in the language itself; the backend is a self-written amd64 emitter — no LLVM, and no vendored QBE.

01 / The four projects

The compiler is the foundation — the other three stand on it.

They share one language and one toolchain. Each card below says what the project actually does today — nothing that is only planned.

01 Stable · v{{site_version}}

JHYY Compiler

The compiler's only implementation is compiler/src0/*.jhyy — there is no bootstrap C compiler in the tree and no vendored backend. It compiles itself, then the compiler it produced compiles it again, and the gate requires the two generations to emit byte-identical assembly. The fixed point is run to, not assumed.

The backend is a self-written in-memory amd64 code emitter, producing PE/COFF on Windows and SysV assembly on Linux. {{stdlib_modules}} standard library modules, with arena as a first-class citizen.

02 Beta · v{{ide_version}}

JHYY IDE

A desktop workbench. Blockly blocks and CodeMirror text share one AST — change one, the other rebuilds. Syntax blocks cannot express survives as an opaque block holding the original source; it never silently disappears. The panel on the right talks to the claude CLI already installed on your machine.

03 Incubating

JiHuiYiYou-OS

An operating system written in this language. The repository currently holds one UEFI x64 boot spike — a bootloader that prints HELLO. It has already measured the EFI calling convention, that the ConOut protocol offset is +64, not +80 (+80 is StdErr, and invisible on OVMF's graphical console), and the isa-debug-exit exit-code path. The design baseline is being rebuilt.

04 Day 0 complete

JiHuiYiYou-for-VEX

Run JHYY directly on the VEX V5 Brain (Xilinx Zynq / Cortex-A9). The route is JHYY emitting ARM machine code directly, not transpiling to C++ — but only clang's slot is replaced; ld and below stay exactly as they are, linking the official SDK into a .bin. Day 0 is complete: every unknown on the VEX side became a measured value, written down as a fact baseline.

Measurement also turned up three traps worth remembering: MSYS2's bundled objdump is x86-only, the SDK's clang is 8.0.0, and the conclusion “the instruction set is ARM-state, fixed 4 bytes” depends on that specific clang version.

03 / What changed · What isn't done

This release fixed three real bugs.

What changed · v{{site_version}}

  • std::arena's arena_reset sized the free window by the default block size — an allocation after a reset could write past the real block and corrupt the heap (measured exit code 0xC0000405).
  • A #[naked] function's label and body travelled on two different channels — the first instruction of the artifact was a run of nop instead of iret, so a bare interrupt entry could not be called.
  • The side-file path was relative to the current working directory — compiling inside your own project directory made #[no_std] fall back to the hosted link line, and the link failed.

The same release also fixed a #[naked] function with parameters segfaulting the compiler itself, and the fact that std::arena had zero test coverage — two regression cases were added, plus a new artifact check no_std_any_cwd; naked_symbol was promoted from KNOWN-FAIL to a real gate.

Full changelog ↗

What isn't done

  • Neither the installer nor the MSI is code-signed — SmartScreen intercepts the first run, and enterprise deployment policies may reject an unsigned MSI outright.
  • amd64 only, four targets; no aarch64, riscv or wasm. The host is Windows x64.
  • The UEFI entry path is not finished (ABI § 12.8).
  • The benchmark ratio is a lower bound on code quality, not a speed pass line — there is no optimizer, so it is the same yardstick as gcc -O0.

These are on the page, not buried in a footnote.
