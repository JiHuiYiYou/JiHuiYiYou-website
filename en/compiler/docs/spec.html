Language Spec v4.0.0

The full spec lives in the repository, not here. Original: docs/abis/jhyy-lang-spec-v4.0.0.md

This page is that spec's guided reading + index + summary of the key conventions. Every item in the body of the spec corresponds to reproducible behaviour in the compiler source; every item on this page does too. Where the two conflict, the original in the repository wins.

The spec is locked at v4.0.0 (2026-10-24, locked together with v4.0.0 final). The toolchain version is a separate matter, see the reference overview.

Key conventions

The table below is the batch you are most likely to get wrong while writing code. The full statements are in the corresponding chapters of the original spec.

Type system

ConventionContent
Primitive typesi8 i16 i32 i64 u8 u16 u32 u64 f32 f64 bool, plus the zero-sized type ()
No charThe type of a character literal is i32, and the value is the Unicode codepoint (the full range U+0000–U+10FFFF)
()Is a ZST (sizeof 0 / alignof 1), but the type position does not accept it: let x: () = (); is a parse error
Compound types*T / [T; N] / [*]T / struct / enum / &T / &mut T / Cap<T> / PhantomData<T> / volatile T
fn(...) typeThe type position does not accept this syntax ⇒ a closure value cannot be passed as a function value
Nominal typesstruct / enum are compared by declaration name, not by layout — the same layout with a different name is a different type
Type aliasesTransparent: type Age = i32 is exactly equivalent to i32
InferenceParameters must be annotated explicitly; local variables are inferred from the initializer expression
Default literal typesUnsuffixed integer → i32; unsuffixed float → f64
Implicit conversionsInteger ↔ float not allowed, as is required

Literals

ConventionContent
Integer basesDecimal / 0x / 0X / 0o / 0O / 0b / 0B; a leading zero means octal (077 = 63)
Underscore separators1_000_000 is not supported (parse error)
Integer suffixesi8 i16 i32 i64 u8 u16 u32 u64
Integer value rangeEvaluated exactly as u64; out of range is a compile error (integer literal out of range), no silent saturation
Float formsOnly N.M (suffixes allowed) — the exponent form 1.0e10 fails to parse
Float suffixesf32 / f64 / f (f = f64)
StringsThe type is *u8 (a NUL-terminated UTF-8 byte string), placed in the .data section; no implicit decay to [*]u8
Booleanstrue / false; the compiler does not normalize to 0/1 — a bool that does not come from a literal may be any byte

Functions and procedures

ConventionContent
Return valueThe last expression of the function body is the return value, no return needed
ParametersMust be annotated explicitly; default parameters and variadic parameters are not supported
NestingNested functions are not supported — every function must be declared at the top level
deferRuns LIFO on the explicit return path; ⚠️ the implicit return of the trailing expression does not trigger defer
#[inline]Actually inlined only when the function body is a single return <expr>;; multiple statements / if-else / loops / recursion all fall back to a plain call

Modules and imports

ConventionContent
SyntaxA single identifier: import mylib; — without the std:: prefix (import std::vec; is a parse error)
Lookup orderNext to the main file → the standard library directory (two-level fallback)
TransitivityRecursive: with main → a → b, main can use the declarations of b
CyclesA cycle reports circular import '...', it does not crash
NamespacesDifferent modules may define functions with the same name; qualify the call with mod::fn()
Multiple filesComposition is done with import, not on the command line — the command line accepts only one input file, and extra .jhyy arguments are silently ignored

enum and match

ConventionContent
enum layoutThe tag is i32, offset 0, increasing from 0 in declaration order
PayloadAt most one payload per variant (Rect(i32, i32) is a parse error) — to hold several fields, replace the payload with a struct
match patternsLiteral / _ / multi-value `pat1 \
Range semantics⚠️ 0..10 in a match is a closed interval (both ends included), while for i in 0..10 is a half-open interval
arm bodyMust be a single expression — you cannot write return, and you cannot write a statement block
arm scopeEach arm is independent, pattern bindings shadow outer variables of the same name, and they do not leak out after the arm ends
ExhaustivenessImplemented: every variant of an enum must be covered or caught by _, otherwise non-exhaustive match: missing variant is reported
Not supportedGuard patterns (Some(x) if x > 0); nested patterns beyond the second level (rejected at compile time)

Pointers and borrows

ConventionContent
Pointer width8 bytes; a null pointer is the integer 0; the arithmetic step is sizeof(T)
&xThe type is *i32; ⚠️ the compiler does not check whether x is mutable — an immutable binding can have its address taken
Pointer differenceThe result of p - q is the number of elements (i64), not the difference in bytes
Member access⚠️ -> is not the member access operator — to reach a field through a pointer write (*p).field
&T / &mut TBoth are 8-byte single pointers; is_mut is a compile-time marker and takes no memory
Not supportedChained &&T; lifetime annotations 'a; reborrow
Borrow checkingOnly a minimum is done — repeated &mut of the same variable in one scope is rejected; full NLL / Polonius is not implemented

FFI (extern fn)

ConventionContent
SemanticsDeclaration only, no function body is generated; the symbol is resolved by ld at link time
SymbolsAssembly symbols are unmangled
VariadicNot supported — every argument of printf must be listed one by one on the JHYY side
CallbacksNot supported
struct / enum by valueNot supported across the FFI boundary
⚠️ No type checkingThe parameter / return types of extern fn are not restricted at compile time — declaring a struct parameter compiles, but it is actually passed by address, which does not match the C ABI (silently mismatched, no error)

Attributes

AttributeWhat it does
#[inline]Hints at inlining (see above)
#[naked]No prologue / epilogue; the function body may only contain asm!(...); it does not take part in sret; the callee has to save the callee-saved registers itself
#[link_section("...")]Only changes the section the symbol lands in, it does not change the calling convention; the section name must be printable ASCII
#[no_std]A module-level attribute; does not link the C runtime startup file, and the entry symbol becomes main; without fn main it reports error: #[no_std] module must define 'fn main()'

Inline assembly and memory barriers

ConventionContent
asm!("...")A single string literal; no operand constraints, no template placeholders, no clobber declarations; AT&T syntax, x86-64 only
PlacementInlined at the current position in the function body (hex-encoded into the dbgasm channel of the IL, and the backend decodes it back in place into the .s) — the early implementation appended it to the end of the .s, which made it dead bytes
Expression positionSyntactically usable, but the return value semantics are undefined ⇒ by convention it is written in statement position
volatile TQualifies primitive types only; the layout is exactly the same as T; within a single thread it guarantees that every load hits memory, that every store writes back, and that they are not reordered
fence_*fence_seq_cst() / fence_acquire() / fence_release() → mfence / lfence / sfence; inlined at the call site; covers x86-64 only
Across threadsvolatile does not provide ordering guarantees across threads — that is what fence_* is for

Other easy traps

ConventionContent
Top-level let mutIt is a runtime global variable, but the initializer must be an integer constant expression; an initializer of a non-integer type is discarded (you read 0 or garbage)
Top-level constOnly top-level const arrays are supported; putting a function call in an element position compiles, but it is not evaluated (you get 0 at runtime)
sizeof / alignofTake a type (not an expression) and return i64; alignof(enum) is always 4
type X = ...No trailing semicolon (with ; it reports unexpected token ';' in expression)
Aggregate equalitystruct / enum / arrays / slices are compared by value; a slice compares only its head (pointer + length), not element by element
Aggregate size comparisona < b and the like on aggregate types is a compile-time error
OverflowSigned integer overflow is defined behaviour (two's-complement wraparound), with no runtime check

The pre-1.0 boundaries

The spec draws two lines itself: the body only documents what is implemented, and appendix B collects every gap.

Explicit gaps (not implemented)

AreaGap
Types() in type position; the fn(...) function pointer type syntax (⇒ a closure cannot be passed as a function value)
BorrowsFull NLL / Polonius borrow checking, lifetime annotations 'a, reborrow, borrows across functions
ClosuresCapturing outer variables — an explicit compile-time error, no silently generated wrong code
ExpressionsBlock expressions (let v = { ... };); a match arm whose body is a statement block
GenericsConstraints <T: Ord>, lifetime generics, const generics, trait objects, HKT
FFIVariadic functions, callback functions, struct / enum by value across the FFI boundary
Cap<T>Field access (.cnode_idx / .depth / .rights); T itself is not parsed
Standard libraryThe f32 versions of std::math and tan / log / exp / floor / ceil
Otherasync / await, std::map, aarch64 / riscv64, the .jhyynb native binary format, the operand constraints of asm! and Intel syntax, guard patterns in match, the exponent form for floats

Implemented but limited (easy to misjudge as a bug)

ItemSymptom
The type of argvIt is written *u8, but it is actually char ** ⇒ *argv only loads 1 byte; to read argv[i] you must first do argv as **u8
Operands of aggregate ==The result of a function call is not accepted (make_p(1) == make_p(2) is a compile-time error); storing it in a variable first with let a = ...; is safe
Fields omitted from a struct literalThey are uninitialized (garbage on the stack), not 0; the compiler does not report a "missing field" either
The type of a struct literal field valueIt must exactly match the field type — writing 7 (inferred as i32) in a u8 field reports field type mismatch
Write protection of immutabilityNot implemented — &x on an immutable binding is legal, and *p = v neither reports an error nor takes effect
Function argument typesNot checked — passing an i32 to a struct parameter compiles, and at runtime the registers are read with the struct layout ⇒ access violation crash
Top-level global variablesOnly integer-typed initializers are evaluated correctly; f64 reads 0, pointers / structs read garbage
const elementsNo const checking — a function call in an element position is not evaluated, and you get 0 at runtime
match rangesClosed intervals (the opposite of for)
deferDoes not cover the implicit return path
Nested patternsBeyond the second level they are not supported (rejected at compile time); the outer tag comparison and the inner payload extraction are both not implemented

The complete item-by-item list is in appendix B of the spec; the entries that carry a ledger number are in docs/internal/workarounds.md.

How spec changes go through

The spec is a locked contract — not a document you edit casually.

  • Any change goes through the RFC process, it does not edit docs/abis/ directly.
  • Locking is more than tagging a release: every "implemented" item in the body of the spec has to find its implementation in compiler/src0/*.jhyy — the self-hosted compiler is the biggest consumer of the spec.
  • After a change to docs/abis/* you have to run the regression suite once (a spec change may affect parsing on the JHYY side).
