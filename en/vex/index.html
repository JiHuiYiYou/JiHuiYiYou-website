VEX V5 Brain: one Zynq.

ARM, a Xilinx Zynq (Cortex-A9 + FPGA), with VFPv3 + NEON. Every number below came out of a measurement, not out of a manual.

SoC Cortex-A9

Xilinx Zynq

A SoC integrating a Cortex-A9 with an FPGA, with VFPv3 + NEON — the hardware base for single-precision floats and SIMD in ARM state.

02 / Route B

What gets replaced is clang's place — ld and below stay.

Not "transpile to C++". But the boundary has to be spelled out.

01 Route A / Route B

Golden reference vs the target.

Route A (step 0, the golden reference): JHYY → C source → clang → .bin.
Route B (the goal): JHYY → ARM machine code (.o) → the official SDK → .bin.
Route B emits an ARM .o, which is then linked against the SDK's lscript.ld / stdlib_0.lib / libv5rt.a, and objcopy produces the .bin.

Route A · clang → Route B · JHYY direct
02 Isomorphic

The same route pros-rs took

Rust emits an .o and links libpros; here JHYY emits an .o and links the official SDK. The difference is that this time it is re-walked with measurements, without that project's sunk cost.

03 The corollary

Three things must be locked, or the two routes cannot be compared

The ABI must be locked (softfp), the entry point must be locked (symbol name main), and the binding surface must be locked (every extern fn maps verbatim to one C symbol) — link whichever library and you accept its ABI.

04 The blocker

JHYY has no ARM target today.

ABI v4.0.0 locks the pointer width at 64 bits, and all four targets are amd64; but V5_DeviceT is a 4-byte C pointer. ⇒ The ARM target must set the pointer width to 4 bytes first; otherwise even extern fn will not line up. This is the first hard blocker of the B phase — it is written into the spec so nobody discovers it the expensive way.

03 / The eight spec items

None of them optional — all eight measured.

The fact baseline document is this project's single source of truth for the numbers and platform facts that may change. Measurement date 2026-11-08, machine Windows 10 + MSYS2, every measurement method a local one (compile / disassemble / readelf / nm), with zero JHYY variables.

Measured 01

Artifact format and signature layout

The SDK's objcopy emits the final format directly; the first 32 bytes are XVX5 + version 1 and the entry point follows right after. No extra converter needed.

Measured 02

What vexStartup does for you

The startup chain is fully closed: clear .bss → stdlib version check → newlib impure data → __libc_init_array → vexMain → __libc_fini_array. Confirmed by disassembly and relocations.

Measured 03

Symbol mangling rules

The C++ vex:: layer has 1404 mangled symbols in libv5rt.a (Itanium mangling ⇒ not touched); the plain C vex*() layer is what JHYY's extern fn binds to directly, with a zero-glue layer.

Locked 04

The softfp / hard decision

Locked to softfp: neither our ELF nor libv5rt.a carries a Tag_ABI_VFP_args tag, and the ARM ABI default is the base standard variant.

Measured 05

The C alignment for a struct by value

There are both packed and non-packed ones. In the whole plain C API there is exactly one struct passed by value (V5_DeviceVisionRgb, ≤4 B ⇒ passed in registers); everything else is passed by pointer.

Verified 06

The minimal binding surface

The exact function names are verified to exist, and there is a list of the verbatim JHYY-side counterparts (change one, change both). The entry symbol must be an unmangled main.

Measured 07

Where to read the field control state

vexCompetitionStatus / vexCompetitionControl; the bit meanings were measured statically (2026-11-09, no hardware needed).

Measured 08 · real robot

The message pump tick rate

100 Hz (scheduler tick = 10 ms), measured on a real Brain on 2026-11-09 — 50 × vexDelay(1) = 500 ms. The last missing item of the eight is now closed.

04 / Three pitfalls

Three things the source warns about explicitly.

01 Tooling

The objdump in MSYS2 is x86-only

On VEX artifacts it reports can't disassemble for architecture UNKNOWN! ⇒ you must use arm-none-eabi-objdump (installed separately for this round, binutils 2.47). readelf reads both.

02 Version

The target says Thumb, the measured artifact is ARM

The SDK's clang is 8.0.0 and its flags say -target thumbv7-none-eabi, but the measured entry point holds ARM state instructions (e59f00a0 is an ARM state LDR literal; Thumb-2 would be f8df). This combination depends on the codegen behaviour of a specific version ⇒ changing the clang version means re-measuring; the conclusion cannot just be carried over.

03 Environment

The measurement environment is Windows 10 + MSYS2

The toolchain paths, the shell and objcopy's behaviour are all bound to this environment. Re-measuring on another machine means re-confirming these three.

05 / Status and boundaries

Which stretch is done, what is still owed.

Both sides belong on this screen — telling only the good half is the same as telling nothing.

✓ Holds today

Step 0 is done, including on real hardware

All eight spec items are measured, the last one on a real Brain (tick rate = 100 Hz, 2026-11-09). The hardware acceptance line passed too: the .bin from Route A really spun a motor — speed = RPM on the output shaft, position = degrees on the output shaft, °/s = RPM × 6; the whole 1 MB heap is usable.

✗ Not measured / not built

The remaining holes are written down here

The display details (bOpaque semantics, text coordinate units) are still to be measured; the motor direction flag shows no effect on read-back (the probe order is suspected); the SD card program.bin burn flow was not walked through (no card inserted this round). In the schedule, Days 1–2 / Day 3 / the B phase have not started at all.

→ Next stretch

Days 1–2: the emitter emits C

A minimal subset plus the minimal binding surface (to start with just vexDeviceGetByIndex / vexDeviceMotorVelocitySet / vexDelay / jhyy_vex_display_puts). C, not C++.

◆ One important distinction

On Day 3, "identical" means behaviour, not bytes

Routes A and B are two different code generators (the .s is bound to differ, and the .o section layout may differ too) ⇒ the five artifact layers .s / .o / ELF / .map / .bin are separate diagnostic evidence, not byte-comparison targets. Comparing layer by layer only exists to locate where the two disagree.

Three rules: do not touch the JHYY main repository directly — experiments happen here, and only a measured result goes back to the main repo, with a separate review; the output of step 0 is knowledge, not code — the emitter is a probe and must not grow into a product; artifacts stay local and are not committed — the .bin / ELF contain libv5rt.a code (VEX-proprietary), so they stay out of the public repo until the "SDK redistribution" question is settled; what is kept is local + a reproducible script + a hash manifest.

Measure first, then move.

This route does not run on plans, it runs on measurements: turn every unknown on the VEX side into a number, and what is left is just work driven by numbers.
