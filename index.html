01 / 四个项目

编译器是地基， 其余三个站在上面。

它们共享同一门语言、同一套工具链。下面每个卡片写的是项目现在真的做到哪一步 —— 不含计划中的部分。

01 稳定 · v4.1.4

JHYY 编译器

编译器唯一的实现是 compiler/src0/*.jhyy —— 树里没有 bootstrap 的 C 编译器，也没有 vendored 的后端。它编译自己，再让编译出来的自己编译自己，而门要求这两代产出的汇编逐字节相同。不动点是跑出来的，不是假设的。

后端是自研的内存内 amd64 代码发射器，产出 Windows 的 PE/COFF 与 Linux 的 SysV 汇编。标准库 8 个模块，arena 是一等公民。

02 测试中 · v0.2.1

JHYY IDE

桌面工作台。Blockly 积木和 CodeMirror 文本共享同一棵 AST —— 改一边，另一边跟着重建。积木表达不了的语法以不透明积木保留原始源码，不会静默丢失。右侧是能直接对话本机 claude CLI 的面板。

IDE 概览 一致性门 277/277 · Windows x64 only
03 孵化中

JiHuiYiYou-OS

用这门语言写的操作系统。仓库目前只有一份 UEFI x64 引导 spike —— 一个打印 HELLO 的 bootloader。它已经实测出 EFI 调用约定、ConOut 的协议偏移是 +64 而不是 +80（+80 是 StdErr，在 OVMF 的图形控制台上根本不可见），以及 isa-debug-exit 的退出码通路。设计基线正在重整。

OS 概览 spike 已实测 4 件事
04 Day 0 已完成

JiHuiYiYou-for-VEX

让 JHYY 直接跑在 VEX V5 Brain（Xilinx Zynq / Cortex-A9）上。路线是 JHYY 直出 ARM 机器码，不是转译成 C++ —— 但换掉的只是 clang 的位置，ld 及以下原样不动，链官方 SDK 出 .bin。第 0 步已完成：VEX 侧的未知数全部变成实测值，写成了事实基线。

实测也踩出了三个必须记住的坑：MSYS2 自带的 objdump 是 x86-only，SDK 的 clang 是 8.0.0，而「指令集 = ARM 态 4 字节定长」这条结论依赖具体 clang 版本。

03 / 最近变化 · 诚实的边界

这一版修的， 是四类「静默算错」。

最近变化 · v4.1.4

  • 超过 16 个参数的调用会被静默丢弃 —— 20 个参数的求和返回 117 而不是 210。
  • SysV 栈传参会覆盖调用者自己的局部变量。
  • 浮点栈传参会破坏 callee-saved 的 %xmm15。
  • 带标识符端点的范围模式会静默匹配一切。

同版还修了：路径缓冲区改为按字节有界、stderr 管道不再死锁、用户程序的 stderr 不再被吞掉、深层嵌套表达式改为报错而不是栈溢出。

完整变更日志 ↗

诚实的边界

  • 安装器与 MSI 都没有代码签名 —— SmartScreen 首次运行会拦，企业分发策略可能直接拒收。
  • 只有 amd64 四个 target，没有 aarch64 / riscv / wasm；宿主只有 Windows x64。
  • UEFI 入口路径尚未完工（ABI § 12.8）。
  • 基准比值是代码质量下限，不是快慢达标线 —— 没有优化器，和 gcc -O0 是同一把尺子。

这些写在页面上，不是藏在脚注里。
