A language that compiles itself.

— a statically-typed, expression-oriented systems language. The compiler is written in itself: compiler/src0/*.jhyy is the only implementation, and the backend is a self-written amd64 emitter — no LLVM, no vendored QBE, no garbage collector. Currently v4.1.4.

01 / Why JHYY

A language, not a framework.

Four opinions we won't compromise on. Each is a small, specific promise — not a marketing tagline.

01 Type system

Static, not gradual.

Types are checked at compile time. There is no any, no implicit conversion, no escape hatch. If a value is i32, it is i32 for the rest of the program. 

type Point = struct { x: i32, y: i32 }
type Shape = enum { Circle(f32), Rect(f32, f32) }
const ORIGIN: Point = Point { x: 0, y: 0 }
fn area(s: Shape) -> f32 {
    match s {
        Circle(r) => 3.14 * r * r,
        Rect(w, h) => w * h,
    }
}

02 Control flow

Expressions, not statements.

if, match, and blocks return values. The last expression of a function is its return — no return keyword needed. 

fn dist_sq(a: Point, b: Point) -> i32 { let dx = a.x - b.x; let dy = a.y - b.y; dx  dx + dy  dy   // ← the return value }

03 Trajectory

A compiler that compiles itself.

The compiler is written in itself. It compiles itself, then compiles itself again, and the gate requires the emitted assembly to be byte-identical across generations. The fixed point is reached, not assumed — the local gate iterates N=10 generations.

C host → JHYY host → Byte-equal closure ✓

04 Specification

One ABI to rule them all.

The language spec (v4.0.0) and the ABI (v4.0.0) are both locked. The spec is a citable contract — third parties can build compatible compilers against it, not just against some commit.

02 / Install

Three minutes from download to hello.exe.

One installer covers the compiler, the .jhyy file association, the VS Code extension and PATH. Since v4.1.0 it also bundles a minimal native ucrt64 toolchain — so MSYS2 is not required to use the compiler. Only building it from source needs MSYS2.

03 / A taste of the language

Four files, the whole grammar.

hello.jhyy 

extern fn puts(s: *u8) -> i32;
fn main_jhyy() -> i32 {
    puts("Hello, world!");
    0
}
type Point = struct { x: i32, y: i32 }
fn dist_sq(a: Point, b: Point) -> i32 {
    let dx = a.x - b.x;
    let dy = a.y - b.y;
    dx * dx + dy * dy
}
fn main_jhyy() -> i32 {
    dist_sq(Point { x: 3, y: 4 }, Point { x: 0, y: 0 })
}
fn fib(n: i32) -> i32 {
    if n < 2 { n }
    else { fib(n - 1) + fib(n - 2) }
}
fn main_jhyy() -> i32 { fib(10) }
type Option = enum {
    Some(i32),
    None,
}
fn unwrap(o: Option) -> i32 {
    match o {
        Some(v) => v,
        None    => 0,
    }
}
fn main_jhyy() -> i32 {
    unwrap(Option::Some(99))
}

04 / The toolchain

A compiler, and everything around it.

You don't only get jhyy.exe. You get an editor extension, an MCP server for Claude Code, and an arena runtime — the four pieces a real language needs to be usable.

Compiler

jhyy compile foo.jhyy -o foo.exe runs the pipeline: Lex → Parse → Sema → IL → 自研 amd64 发射器 → native. Diagnostics carry line + column. Exit codes match clang. No GC, no malloc hot-path — one arena_alloc, one arena_free at the end.

  • ~39 000 LOC JHYY
  • ·51 个 .jhyy 文件
  • ·自举 · 唯一实现

VS Code extension

First-class .jhyy language support: syntax highlighting, snippets, problem matchers, and a configured F6 shortcut to compile & run via Code Runner.

05 / 现状与边界

What works, and what doesn't.

JHYY 是 pre-1.0 的项目：自举成立、回归全绿，但它还不是 C 或 Rust 的替代品。 这一屏把两边都写出来——只讲做到了什么，等于不讲。

✓ 已经成立

自举，且被验证过

编译器唯一的实现是 JHYY。它编译自己，再让编译出来的自己编译自己，门要求两代产出的汇编 逐字节相同。回归 279 PASS / 0 FAIL / 20 SKIP（共 299 条）， artifact 检查 19 PASS / 0 FAIL，问题台账 217 条里 ACTIVE = 0。

spec v4.0.0 · ABI v4.0.0 · binary format v1.0.0
✗ 还没有

边界写在明面上

只有 amd64——没有 aarch64、没有 riscv、没有 wasm。宿主只有 Windows x64。 UEFI 入口路径尚未完工（ABI § 12.8）。没有 traits，没有 GC，借用检查目前只有最小的一层。 安装器和 MSI 未签名。裸机目标只到 freestanding，链接仍需外部 ld。

裸机能力现状
→ 正在推

三个方向同时在跑

ARM 目标在 for-VEX 项目里——JHYY 直出 ARM 机器码，链官方 SDK。 操作系统的设计基线正在重整，当前只有一份 UEFI x64 引导 spike。 IDE把积木和文本接到同一棵 AST 上。

看家族另外三个项目
◆ 一条重要的区分

「逐字节相同」证明的是什么

自举闭环证明的是世代确定性——编译器精确地复现自己， 这是一条关于「确定性」的陈述，不是关于「语义正确性」的。语义正确性由回归套件单独覆盖。 这是经典的 trusting trust 缺口，两件事不能混为一谈。

06 / By the numbers

No VM. No JIT. No runtime.

自研发射器在编译期直接产出 amd64 机器码。随附的运行时只有一个小 C 支撑库 （约 156 行），而且连它都可以不要——#[no_std] 下不链任何 C 运行时。 下面每个数字都注明了测量条件；基准比值的口径写在脚注里。

编译到 .s
 
本机实测（Windows 10 / i7-8550U / 2026-11-08，min of 8）。Lex → Parse → Sema → IL → 自研 amd64 发射器，产出汇编文本。
编译 + 链接
 
链接步骤由外部 gcc 驱动（现编现链 runtime + helpers），占掉绝大部分时间。只想看汇编用 jhyy build。

PASS 279 · FAIL 0 · SKIP 20，共 299 条。另有 artifact 检查 19 PASS / 0 FAIL，问题台账 217 条中 ACTIVE = 0。
基准比值 vs gcc -O0
1.42× – 5.37×
9 个任务 / 4 条覆盖轴（整数与位运算、f64、堆、字节），min-of-15 墙钟。这是代码质量下限的比值，不是快慢的达标线——见下方说明。

关于这个比值：JHYY 目前没有优化器，产出的是接近 -O0 的代码， 所以拿 gcc -O0 作分母才是同一量纲的比较；gcc -O2 只作参考，不是通过/失败的标准。 比值已扣除测量底噪（进程创建 + 运行时启动；JHYY 的 shim 比裸 C 贵约 6 ms）。 其中 ack 与 nq 两题底噪占比超过 25%，口径不可靠，因此不报比值。 另外这套题测的是代码生成，不是标准库质量——标准库是另一根轴。 完整快照见仓库 bench/baseline/RESULTS-2026-11-04.md。

07 / About

北京 · RDFZ ICC · CS,
一个编译器,以及它身后的 OS。

机会翼游(JHYY)的作者。两年前在 B 站看到朝歌大佬的 z 语言,受了点启发,就开始了 JHYY。一开始没什么方向,后来慢慢成形:rust-like + arena allocator,再后来确定了自举优先的方针 — 现在它已经自举了——编译器唯一实现就是 JHYY 自己,两代产物要求逐字节相同,不动点是跑出来的。后端也是自己写的 amd64 发射器,约 13 400 行,没有 LLVM 也没有 vendor 进来的 QBE。

自举之后做什么?借强类型 + 编译快的优势,我们开始构想自研 OS。先后确定了 Cap<T> capability、lang-debug ABI、以及 GUI 三个方向,目标 JiHuiYiYou-OS microkernel。

写编译器之外偶尔也做点 Godot 独立游戏。GitHub 上能找到我。

项目初创不久,目前还只是一个草台班子(只有我一个人)。欢迎大家提建议、参与讨论、共同进步。
