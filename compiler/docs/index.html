一段话讲清这个项目

JHYY 是一门用自己写的系统编程语言。compiler/src0/*.jhyy 是编译器唯一的实现 ——树里没有 bootstrap 的 C 编译器，也没有 vendored 进来的后端。编译器先编译自己， 再让编译出来的自己编译自己，而门要求这两代之间产出的汇编逐字节相同。 不动点是跑出来的，不是假设出来的。

后端是自己写的 amd64 代码生成器。Windows 上产出 PE/COFF，Linux 上产出 ELF。 没有 LLVM，没有 QBE，没有垃圾回收，也没有托管运行时；随附的运行时只有一个很小的 C 支撑库。

想看完整版，读 README （中文版是 README.zh-CN.md）。

三件不一样的事

  1. 自举是被验证过的。 不是「编译器能编译自己」，而是「第二代与第一代逐字节相同」 ——每次构建都查，结果随每次发布一起公开。
  2. 没有 vendored 后端。 amd64 代码生成器是 JHYY 自己写的代码。它消费的中间表示 也是 JHYY 自己的格式：借了 QBE 的语法做起点，但没有任何 QBE 代码被 vendored、 被链接或被执行。
  3. 没有 GC，没有托管运行时。 显式指针、可预期的类 C ABI，以及面向 freestanding 目标的 no_std 模式。

这个 wiki 怎么维护

wiki 是手写的伴生文档，不是生成出来的产物——它的讲解顺序和仓库不一样，也允许 更口语一些。三条规矩让它保持诚实：

  1. 不复述数字。 一个把版本、数量或体积抄下来的 wiki 页面，写完第二天就是错的。 页面改为指向拥有那个数字的文档。
  2. 不复述台账。 已知限制住在语言规范的附录 B 和公开的 workaround 台账里， wiki 只负责指路。
  3. 欢迎订正。 如果某页和仓库冲突，仓库是对的——提个 issue，说明哪一页过时了。
