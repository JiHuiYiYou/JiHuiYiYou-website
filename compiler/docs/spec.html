规范全文在仓库里，不在这里。 原文：docs/abis/jhyy-lang-spec-v4.0.0.md

关键约定

下表是写代码时最容易记错的那批。完整表述在规范原文对应章节。

类型系统

约定内容
基础类型i8 i16 i32 i64 u8 u16 u32 u64 f32 f64 bool，外加零大小类型 ()
没有 char字符字面量的类型是 i32，值是 Unicode codepoint（全码点 U+0000–U+10FFFF）
()是 ZST（sizeof 0 / alignof 1），但类型位置不认它：let x: () = (); 是解析错误
复合类型*T / [T; N] / [*]T / struct / enum / &T / &mut T / Cap<T> / PhantomData<T> / volatile T
fn(...) 类型类型位置不认这个语法 ⇒ 闭包值无法当函数值传递
名义类型struct / enum 按声明名比较，不是按布局——布局相同、名字不同就是不同类型
类型别名透明：type Age = i32 与 i32 完全等价
推断参数必须显式标注类型；局部变量从初始化表达式推断
默认字面量类型无后缀整数 → i32；无后缀浮点 → f64
隐式转换整数 ↔ 浮点不允许，必须 as

字面量

约定内容
整数进制十进制 / 0x / 0X / 0o / 0O / 0b / 0B；前导零按八进制（077 = 63）
下划线分隔1_000_000 不支持（解析错误）
整数后缀i8 i16 i32 i64 u8 u16 u32 u64
整数取值范围按 u64 精确求值；越界编译报错（integer literal out of range），不静默饱和
浮点形式只支持 N.M（可带后缀）——指数写法 1.0e10 解析失败
浮点后缀f32 / f64 / f（f = f64）
字符串类型是 *u8（NUL 结尾的 UTF-8 字节串），落 .data 段；没有隐式 decay 到 [*]u8
布尔true / false；编译器不做 0/1 归一化——非字面量来源的 bool 可能是任意字节

函数与过程

约定内容
返回值函数体最后一个表达式即返回值，不需要 return
参数必须显式标注类型；不支持默认参数与变参
嵌套不支持嵌套函数——所有函数必须在顶层声明
defer在显式 return 路径上按 LIFO 执行；⚠️ 函数体末表达式的隐式返回不触发 defer
#[inline]只在函数体是单条 return <expr>; 时真正展开；多语句 / if-else / 循环 / 递归都回退成普通 call

模块与导入

约定内容
语法单个标识符：import mylib;——不带 std:: 前缀（import std::vec; 是解析错误）
查找顺序main 文件旁边 → 标准库目录（两级回落）
传递性递归：main → a → b 时 main 能用 b 的声明
循环成环报 circular import '...'，不崩溃
命名空间不同模块可定义同名函数，用 mod::fn() 限定调用
多文件组合靠 import，不靠命令行——命令行只接受一个输入文件，多余的 .jhyy 参数被静默忽略

enum 与 match

约定内容
enum 布局tag 是 i32，offset 0，从 0 起按声明顺序递增
payload一个变体最多带一个 payload（Rect(i32, i32) 是解析错误）——要装多个字段就把 payload 换成 struct
match 模式字面量 / _ / 多值 `pat1 \
范围语义⚠️ match 里的 0..10 是闭区间（含两端），而 for i in 0..10 是半开区间
arm body只能是单个表达式——不能写 return，也不能写成语句块
arm 作用域每个 arm 独立，模式绑定遮住外层同名变量，arm 结束后不外泄
穷尽性已实装：enum 上每个变体必须被覆盖或由 _ 兜底，否则报 non-exhaustive match: missing variant
不支持guard pattern（Some(x) if x > 0）；二层以上的嵌套 pattern（编译期拒绝）

指针与借用

约定内容
指针宽度8 字节；空指针是整数 0；算术步长是 sizeof(T)
&x类型是 *i32；⚠️ 编译器不检查 x 是否可变——不可变绑定也能取地址
指针差p - q 的结果是元素个数（i64），不是字节差
成员访问⚠️ -> 不是成员访问运算符——通过指针访问字段写 (*p).field
&T / &mut T都是 8 字节单指针；is_mut 是编译期标记，不占内存
不支持链式 &&T；生命周期标注 'a；reborrow
借用检查只做到最小程度——同一作用域内重复 &mut 同一变量被拒绝；完整 NLL / Polonius 未实装

FFI（extern fn）

约定内容
语义只声明、不生成函数体；链接期由 ld 解析符号
符号汇编符号不加修饰
变参不支持——printf 的每个参数必须在 JHYY 侧逐个列出
回调不支持
struct / enum 按值不支持跨 FFI 边界
⚠️ 类型不检查extern fn 的参数 / 返回类型不做编译期限制——声明 struct 参数能编译通过，但实际按地址传，与 C ABI 不符（静默不符，无报错）

属性

属性作用
#[inline]提示内联（见上）
#[naked]无 prologue / epilogue；函数体只能含 asm!(...)；不参与 sret；被调用方需自行保存 callee-saved 寄存器
#[link_section("...")]只改符号落入的 section，不改变调用约定；section 名必须是可打印 ASCII
#[no_std]模块级属性；不链接 C 运行时启动文件，入口符号改为 main；没有 fn main 会报 error: #[no_std] module must define 'fn main()'

内联汇编与内存屏障

约定内容
asm!("...")单字符串字面量；不支持操作数约束、模板占位符、clobber 声明；AT&T 语法，x86-64 only
落点内联在函数体当前位置（hex 编码进 IL 的 dbgasm 通道，后端在原位解回写入 .s）——早期实现把它 append 到 .s 末尾，成为死字节
表达式位置语法上可用，但返回值语义未定义 ⇒ 惯例写在语句位置
volatile T只修饰基础类型；布局与 T 完全一致；保证单线程内每次 load 命中内存、每次 store 写回、不重排
fence_*fence_seq_cst() / fence_acquire() / fence_release() → mfence / lfence / sfence；内联在调用点；只覆盖 x86-64
跨线程volatile 不提供跨线程顺序保证——那要靠 fence_*

其他容易踩的

约定内容
顶层 let mut是运行时全局变量，但初始化器必须是整数常量表达式；非整数类型的初始化器被丢弃（读到 0 或垃圾）
顶层 const只支持顶层 const 数组；元素位置放函数调用能编译通过，但不会被求值（运行时取到 0）
sizeof / alignof接受类型（不是表达式），返回 i64；alignof(enum) 恒为 4
type X = ...结尾不带分号（带 ; 报 unexpected token ';' in expression）
聚合相等struct / enum / 数组 / 切片按值比较；切片只比头（指针 + 长度），不逐元素
聚合大小比较a < b 这类对聚合类型编译期报错
溢出有符号整数溢出是定义行为（二进制补码环绕），无运行时检查

预 1.0 的边界

规范自己划了两条线：正文只写已实装的行为，附录 B 收所有留白。

明确留白（未实装）

领域留白
类型() 在类型位置；fn(...) 函数指针类型语法（⇒ 闭包不能当函数值传递）
借用完整 NLL / Polonius 借用检查、生命周期标注 'a、reborrow、跨函数借用
闭包捕获外层变量——编译期明确报错，不静默生成错误代码
表达式块表达式（let v = { ... };）；match arm 的 body 是语句块
泛型约束 <T: Ord>、生命周期泛型、const generic、trait objects、HKT
FFI变参函数、回调函数、struct / enum 按值跨 FFI 边界
Cap<T>字段访问（.cnode_idx / .depth / .rights）；T 本身不被解析
标准库std::math 的 f32 版本与 tan / log / exp / floor / ceil
其他async / await、std::map、aarch64 / riscv64、.jhyynb 原生二进制格式、asm! 的操作数约束与 Intel 语法、match 的 guard pattern、浮点指数写法

已实装但受限（容易误判成 bug）

项现象
argv 的类型写成 *u8，实际是 char ** ⇒ *argv 只 load 1 字节；读 argv[i] 必须先 argv as **u8
聚合 == 的操作数不接受函数调用结果（make_p(1) == make_p(2) 编译期报错）；先 let a = ...; 存进变量就安全
struct 字面量省略的字段未初始化（栈上的垃圾），不是 0；编译器也不报「缺字段」
struct 字面量字段值类型必须精确匹配字段类型——u8 字段写 7（推断成 i32）报 field type mismatch
不可变性的写保护未实装——&x 对不可变绑定合法，*p = v 不报错也不生效
函数实参类型不检查——把 i32 传给 struct 形参能编译通过，运行时按 struct 布局读寄存器 → 访问违例崩溃
顶层全局变量只有整数类型的初始化正确求值；f64 读到 0，指针 / struct 读到垃圾
const 元素不做 const 检查——元素位置放函数调用不会被求值，运行时取到 0
match 范围闭区间（与 for 相反）
defer不覆盖隐式返回路径
嵌套 pattern二层以上不支持（编译期拒绝）；外层 tag 比较与内层 payload 提取都未实装

完整的逐条清单在规范附录 B，带台账编号的条目在 docs/internal/workarounds.md。

规范改动怎么走

规范是锁定的契约——不是随手改的文档。

  • 任何改动走 RFC 流程，不直接改 docs/abis/。
  • 锁版不是打个标签就完事：规范正文里的每一条「已实装」都要在 compiler/src0/*.jhyy 里找到对应实现——自举编译器本身就是规范的最大消费者。
  • docs/abis/* 变更后要跑一遍回归（规范改动可能影响 JHYY 端的解析）。
