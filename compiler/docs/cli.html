jhyy 只有一个二进制、四个子命令、两个全局选项。下面是逐条核实过的行为表 —— 含产物名和退出码 —— 以及三个会咬人的命令行怪癖。

1. 命令表

命令用途产物
jhyy compile <file.jhyy> [-o output]编译 + 链接<output>.exe；中间的汇编（<output> + .s）也留在盘上
jhyy build <file.jhyy> [-o base]只编译，不链接<base>.s
jhyy run <file.jhyy>编译 + 链接 + 执行临时产物 <name>_run.exe（跑完留在盘上）
jhyy dump <file.jhyy>只解析，打印 AST 树打到 stdout

不带 -o 时，输出名取输入文件的基名：jhyy compile hello.jhyy ⇒ hello.exe， jhyy build hello.jhyy ⇒ hello.s。

-o 是基名，后缀自动补：-o foo ⇒ foo.s / foo.exe；-o foo.s ⇒ 仍是 foo.s（不会变成 foo.s.s），-o foo.exe ⇒ foo.exe（旁边的汇编是 foo.exe.s）。

2. 三个子命令的差别（重点）

compile / build / run 是同一条流水线的三个切点：

.jhyy → lex → parse → sema → IL → 自研 amd64 后端 → .s → gcc + ld → .exe
                             └── build   = 到 .s 为止
                                        └── compile = 再走 gcc + ld
                                                     └── run = 再执行
buildcompilerun
解析 + 语义分析是是是
生成 .s是是是
调 gcc / ld 链接否是是
执行否否是

两条等价路径

jhyy build   x.jhyy -o out            # ⇒ out.s
jhyy compile --no-link x.jhyy -o out  # ⇒ out.s

两条产出的 .s 逐字节相同 —— 包括 #[link_section] 生成的 .section 指令 （两条路径都套用同一段 section 处理）。仓库里有一条 artifact check （link_section_build）钉住这个等价关系。

实测：对一个同时带 #[link_section] 和 #[naked] 的文件，两条路径的 .s cmp 结果是完全一致。

一个和帮助文案不一致的地方

jhyy --help 里写的是 compile ... (a lib without main is compiled only)。 实测：拿一个没有 main_jhyy 的文件跑 jhyy compile，.s 确实产出了，但链接 步骤照样会跑并失败（collect2.exe: error: ld returned 1 exit status），退出码 1。 ⇒ 想只拿汇编，用 jhyy build 或 jhyy compile --no-link。

3. 选项

选项作用
--target=<triple>选目标，默认 amd64_win。位置任意（子命令前后都行）；给多个时最后一个生效
--no-link只产出 .s，跳过链接。位置任意（子命令前后都行）
--help打印完整帮助并退出 0。任意位置都能触发 —— jhyy --help 和 jhyy compile --help 打的是同一份

不带任何参数跑 jhyy 打的也是同一份完整帮助。

四个目标

三元组调用约定运行时这份构建能链接吗
amd64_winMS x64hosted（链 C 运行时）能（唯一能链的）
amd64_sysvSysV AMD64hosted不能，必须 --no-link
amd64_win_freestandingMS x64freestanding（UEFI）不能，必须 --no-link
amd64_sysv_freestandingSysV AMD64freestanding不能，必须 --no-link

freestanding 相关的三点：

  1. freestanding 只切「调用约定归属 + 入口钩子」，不切链接方式。 链接行由源文件里有没有 #[no_std] 决定 —— 详见 裸机与内核开发。
  2. 交叉目标故意拒绝链接。不带 --no-link 直接报错、退出 1：
   jhyy: refusing to link a cross target - this build's linker always emits a Windows .exe (via the bundled toolchain).
         Use --no-link, then link the .s with a toolchain that matches the target.
  1. --target 不切换 PE / ELF 产出 —— 容器格式由宿主 ld 决定（ABI § 12.9）。

完整的交叉编译三步

# 1. 在 Windows 上出 .s（交叉目标必须带 --no-link）
jhyy compile --target=amd64_sysv_freestanding --no-link prog.jhyy -o prog
#    ⇒ prog.s

# 2. 在 Linux 上链成静态 ELF
gcc -nostdlib -static -T runtime/linux_elf/link.ld -o prog.elf \
    runtime/linux_elf/crt0.S prog.s

# 3. 跑
./prog.elf

4. 三个必须知道的怪癖

4.1 没有 jhyy --version

它从来就不存在。跑它会打：

jhyy: unknown option --version
(try `jhyy --help`)

然后退出 1。版本横幅在 jhyy --help 的第一行 —— 不带参数跑 jhyy 打的是 同一份帮助，banner 也在第一行。

4.2 命令行只接受一个输入文件

多余的 .jhyy 参数被静默忽略 —— 不报错、不警告。实测 jhyy compile --no-link main.jhyy lib.jhyy -o multi 退出码 0，产出的 multi.s 里只有 main_jhyy 的符号，lib.jhyy 定义的 lib_helper 一个字都没有。

多文件请用 import 组合：在 main.jhyy 里写 import lib;，编译器沿 import 图 把 lib.jhyy 一起编进来。

4.3 不认识的选项会被拒绝

$ jhyy compile --foo main.jhyy
compile: unknown option --foo
(try `jhyy --help`)

退出 1。它不会把这个 flag 当成文件名去打开。build 和 run 各有自己的前缀 （build: unknown option --foo / run: unknown option --foo）。

5. 退出码

情形退出码
--help / 无参数0
build / compile 成功0
run 成功被运行程序的退出码
未知选项 / 未知命令 / 未知 target1
语法错误 / 语义错误1（诊断打到 stderr，带 file:line:col）
文件打不开1
交叉目标拒绝链接1
链接失败1

jhyy run 会把被运行程序的退出码原样传出来：程序 return 42 ⇒ jhyy run 退出 42。

诊断长这样：

bad.jhyy:1:33: error: unexpected token ';' in expression
bad.jhyy:1:29: error: expected ;, got return
parse errors

另外两条错误路径的措辞：

$ jhyy compile                        # 没给输入文件
usage: jhyy compile <file.jhyy> [-o output] [--no-link]

$ jhyy frobnicate x.jhyy             # 未知子命令
jhyy: unknown command 'frobnicate'
(commands: compile / build / run / dump - try `jhyy --help`)

关于「退出码和 clang 一致」：README、README.zh-CN、CHANGELOG 和两份规范里 都没有这条表述。实测出来的语义就是上面这张表 —— 成功 0、失败 1，run 额外 透传被运行程序的退出码。

在 MSYS2 bash 里取退出码要小心：bash 会把退出码截成 8 位（值 & 0xFF）。 要精确的退出码，用 harness 或 Python subprocess，别读 $?。

6. 速查

# 编译并链接成 exe
jhyy compile hello.jhyy

# 只出汇编（交叉目标必须走这条）
jhyy build hello.jhyy -o hello
jhyy compile --no-link --target=amd64_sysv_freestanding hello.jhyy -o hello

# 编译 + 链接 + 跑
jhyy run hello.jhyy

# 只看语法树
jhyy dump hello.jhyy

# 看编译器自己的帮助（版本横幅在第一行）
jhyy --help
