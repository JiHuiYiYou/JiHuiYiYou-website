CH-02 一段源码 / SOURCE READ 
type Point = struct { x: i32, y: i32 }

fn dist_sq(a: Point, b: Point) -> i32 {
    let dx = a.x - b.x;
    let dy = b.y - a.y;
    dx * dx + dy * dy          // 无分号，末行即返回值
}

fn classify(n: i32) -> *u8 {
    match n {                       // 带穷尽性检查
        0       => "zero",
        1..10   => "single digit",
        10 | 20 => "round number",
        _        => "other",
    }
}

extern fn printf(fmt: *u8, val: i32) -> i32;   // FFI 到 C

fn main_jhyy() -> i32 {
    let p = Point { x: 3, y: 4 };
    printf("d² = %d\n", dist_sq(p, Point { x: 0, y: 0 }));
    let s = "机会翼游";              // UTF-8 原生字面量
    0
}

这是什么 / WHAT

NAV
DESCRIPTION

JHYY（机会翼游）是一门自研的、静态类型的、表达式导向的编译型系统编程语言。 源码 .jhyy 进，自研后端出 x86-64 原生二进制出， 中间没有解释器、没有虚拟机、没有垃圾回收。

它不为上生产而写。它存在的第一理由是：能不能用一门语言，把这门语言的编译器写出来， 并且第二遍第三遍一直编下去，结果分毫不差。

THREE OBJECTIVES
  • 自举能力 —— 编译器用自身语言写自身，达成字节相同闭环（v1.0.0 达成）
  • 原生性能 —— 无运行时 / 无 GC，直接产出机器码
  • 系统级能力 —— inline asm / volatile / naked / no_std / &mut + lifetime，为写操作系统准备
SELF-HOST 100%

工程账本 / WORKAROUND LEDGER

LEDGER

每个已知缺陷编一个号（W-NNN），修不好就写进账本、写清状态、留证据。 修错了就回滚，把回滚也记下来。下面这段是账本上的真实一页。

W-101 · derived address tracking
#1REVERTEDbitmap 方案错方向
#2REVERTEDalloc pool disjoint 假设错
#3REVERTED深审计 checklist 后仍是错的
#4REVERTEDplan 方向被审计推翻
#5–6REVERTED改对了方向，写错了参数个数
#7SUCCESSgdb 一轮 RCA 拿到冒烟枪：少传了 state 指针

第七次成功的原因不是更聪明，是不再猜：先用 gdb 抓到 rcx=NULL 的那一行，再回头改。三行调用点改成三参数形式，歧义消失。

WHY IT MATTERS

大多数项目的 bug 列表读起来像功能缺陷清单。这个项目的账本读起来像 推理失败记录：哪一次假设错了、为什么错、拿什么证据推翻的。 对一个宣称自举的编译器来说，这比任何一处代码都更能说明它是不是真的。

OPEN ITEMS
  • W-097 —— 25 处多字段访问 emit 待真修（跨 10 个模块）
  • W-072 —— 多字段访问 emit
  • 规则：正式版发布前，活跃与延期项必须清零。
